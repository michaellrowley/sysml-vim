INTRODUCTION                                                *sysml-vim-intro*

sysml-vim provides a Vim/Neovim frontend for the bundled `sysml` backend CLI.

==============================================================================
COMMANDS                                                  *sysml-vim-commands*

:v2 {subcommand} [arguments]  Run a plugin command; no arguments opens help.
:v2 check [path]              Run parser/reference diagnostics.
:v2 check-workspace [path]    Validate workspace (default: cwd).
:v2 tree [path]               Open model structure tree buffer.
:v2 view [type] [focus]       Open semantic text view.
:v2 graph [focus]             Open a structural diagram with feature compartments.
:v2 find [kind] [name]        Populate quickfix with semantic query.
:v2 definition [name]         Jump to definition (default: <cword>).
:v2 references [name]         Quickfix references (default: <cword>).
:v2 hover [name]              Show hover/details buffer.
:v2 relationships [name]      Open dependency-centric view.
:v2 requirements [name]       Open requirements-centric view.
:v2 traceability [name]       Open traceability-centric view.
:v2 health                    Show backend health and capabilities.
:v2 log                       Show plugin/backend log messages.
:v2 restart                   Restart the RPC backend when active.
:v2 help                      Open this help page.

:v2g [focus]                  Alias for :v2 graph.
:v2h                          Alias for :v2 help.
:v2c [path]                   Alias for :v2 check.
:v2cw [path]                  Alias for :v2 check-workspace.
:v2d [name]                   Alias for :v2 definition.
:v2f [kind] [name]            Alias for :v2 find.
:v2hea                        Alias for :v2 health.
:v2ho [name]                  Alias for :v2 hover.
:v2l                          Alias for :v2 log.
:v2r [name]                   Alias for :v2 references.
:v2rel [name]                 Alias for :v2 relationships.
:v2req [name]                 Alias for :v2 requirements.
:v2res                        Alias for :v2 restart.
:v2tra [name]                 Alias for :v2 traceability.
:v2t [path]                   Alias for :v2 tree.
:v2v [type] [focus]           Alias for :v2 view.

The original :Sysml* commands remain available for compatibility.

`:v2 check` uses the current model buffer's text, including unsaved changes.
`:v2 check-workspace` also includes unsaved text from loaded model buffers in
the workspace. These checks require a working RPC backend when model buffers
have unsaved changes.

MAPPINGS                                                *sysml-vim-mappings*

<Plug>(sysml-definition)
<Plug>(sysml-references)
<Plug>(sysml-hover)
<Plug>(sysml-next-diagnostic)
<Plug>(sysml-prev-diagnostic)
<Plug>(sysml-graph-next-node)
<Plug>(sysml-graph-prev-node)
<Plug>(sysml-graph-next-edge)
<Plug>(sysml-graph-prev-edge)
<Plug>(sysml-graph-inspect)
<Plug>(sysml-graph-left)
<Plug>(sysml-graph-right)
<Plug>(sysml-graph-up)
<Plug>(sysml-graph-down)
<Plug>(sysml-graph-mouse)

Default mappings (if free):
  gd  -> definition
  gr  -> references
  K   -> hover

In :v2 graph buffers, ]n / [n move to the next / previous node and
]e / [e move to the next / previous edge and highlight its route and edge
entry. These defaults respect existing mappings and can be remapped through
the corresponding <Plug> mappings. Press <CR> on a selected node or edge to
open its projected details in a read-only tab. Interconnection-edge details
include connected part/port trees and projected flows or bindings.
Arrow keys trace outward from the selected box and move to the first node hit
in that direction. If no ray intersects a node, they move to the nearest node
in that half-plane. With mouse support enabled ('mouse'), hovering over a node
or rendered edge selects it in Neovim; in Vim, click to select because Vim
does not report pointer-hover events.

CONFIGURATION                                        *sysml-vim-configuration*

let g:sysml_default_view = 'composition'
let g:sysml_use_rpc = 1
let g:sysml_rpc_timeout_ms = 120000

The plugin defaults to sysml and sysml-rpc in the dedicated virtual
environment under SYSML_VIM_INSTALL_ROOT/venv (or
XDG_DATA_HOME/sysml-vim/venv). To configure a custom installation, set both
commands together:

  let g:sysml_backend_cmd = expand('~/.local/share/sysml-vim/venv/bin/sysml')
  let g:sysml_rpc_cmd = expand('~/.local/share/sysml-vim/venv/bin/sysml-rpc')

Do not mix commands from different Python environments. See
docs/configuration.md for details.

VIEWS                                                        *sysml-vim-views*

Supported view types:
  package, tree, composition, connections, requirements,
  traceability, dependencies, behavior, state

Use `:v2 view {type}` or `sysml view {type}`.
Tree, graph, and semantic views open in a dedicated tab, leaving the source tab
available. Open views refresh after edits to loaded SysML/KerML buffers in the
same workspace, including unsaved text sent over the RPC backend.
:v2 graph without a focus argument shows the whole workspace; provide an
element name to limit the graph.
When the focused element is a SysML view usage, its typed view definition
selects the presentation. Standard definitions supported are GeneralView,
InterconnectionView, ActionFlowView, StateTransitionView, SequenceView,
GeometryView, GridView, and BrowserView. Custom view definitions inherit a
presentation when their `specializes` relationship to a standard definition
is available in the language-server projection. Use `:V2g bleTraceView` or
`:v2 view composition bleTraceView`; the view usage's name does not choose the
presentation.

Interconnection views show parts with their nested features and projected
connectors; port dots mark connection endpoints, and connector/item-flow
labels appear on routes when there is room. Action-flow views emphasize
actions, parameters, and flow
relationships; state-transition views emphasize states and transitions.
Sequence views show lifelines and projected events in source order. Geometry
views plot numeric projected positions in orthographic views; without
coordinates they show an inventory rather than inferred placement. Grid views
show a table, and Browser views show a hierarchy that can be folded with
`zc` / `zo` and opened or closed globally with `zR` / `zM`.

Only the selected model projection is rendered. Sequence order is not
simulated execution time, and GeometryView is not a full 3D shape renderer.
Generic graph views continue to show definition kind/name headers and
contained usages in feature compartments, with orthogonal relationship routes
and an outer gutter for backward or cyclic relationships.

SysML folds are open by default. Adjust `foldlevel` in your ftplugin if you
prefer collapsed folds.

LIMITATIONS                                            *sysml-vim-limitations*

Model commands require Node.js 20+ and the third-party sysml-v2-lsp package.
The backend discovers the package under SYSML_VIM_INSTALL_ROOT or the
XDG_DATA_HOME default. Set SYSML_LSP_SERVER to its dist/server/server.js
entry point when installing elsewhere. The installer configures this variable.
See docs/lsp-parser.md for full setup.

The ANTLR grammar is derived from OMG textual KEBNF by a community project.
The LSP project's semantic checks are not the official Pilot validator and
are not a claim of complete SysML/KerML conformance. The index and views expose
selected model projections, not a complete semantic API.
